## Q1：Claude 的回答可以商用嗎？

**簡短答案：可以，但要帶點常識。**

根據 Anthropic 的使用條款，你用 Claude 生成的內容（文字、程式碼、圖表等）的版權歸你所有。你可以用在：
- 商業產品和服務
- 客戶專案
- 內部工具
- 以你名義發表的內容
- 你販售的產品

**要注意的地方：**

| 情境 | 建議 |
|------|------|
| 不經審查直接使用 AI 產出 | 一定要檢查和編輯 —— 你要對正確性負責 |
| 生成關於真實人物或品牌的內容 | 確認事實正確，留意潛在的誹謗問題 |
| 為受規管的行業產出內容（醫療、法律、金融） | 正式發布前讓專業人士 review |
| 轉售 Claude 本身的存取權 | 不允許 —— 你可以賣你做的東西，但不能賣 Claude 的使用權 |

**黃金法則：** 你擁有產出的內容，但你也要對它負責。這就像請了一個代筆 —— 文字是你的、責任是你的、功勞是你的、查證的義務也是你的。

*隨時查看最新的 [使用條款](https://www.anthropic.com/terms) 確認政策是否更新。*

## Q2：我的資料上傳到 Claude 安全嗎？

**簡短答案：基本上安全，但細節取決於你的方案。**

| 關心的事 | Free 方案 | Pro 方案 | Team 方案 |
|---------|-----------|----------|-----------|
| **資料會被拿去訓練 AI？** | 可能（可在設定中關閉） | 預設不會 | 不會 |
| **資料會被儲存？** | 暫時性，供對話使用 | 暫時性 | 有額外保護措施 |
| **Anthropic 員工看得到我的資料？** | 僅限少數安全/濫用審查情況 | 同上 | 更嚴格的存取控制 |
| **資料有加密嗎？** | 有，傳輸中和儲存時 | 有 | 有 |

**實用建議：**

| 敏感程度 | 建議 |
|---------|------|
| 公開資訊（研究、一般問題） | 什麼方案都行 |
| 內部工作文件 | Pro 方案 + 檢查隱私設定 |
| 公司機密資料 | Team 方案或先跟你的 IT 部門確認 |
| 極度敏感（個資、財務記錄、健康資料） | 先查你公司的資料治理政策 |

**關閉訓練的設定：** 在 Free 方案中，進入 Settings > Privacy，關閉允許對話被用於改善模型的選項。這會給你更多對資料的控制權。

## Q3：為什麼 Claude 有時候會「拒絕」我的請求？

**簡短答案：安全護欄。** Claude 被設計成 helpful、harmless、honest（有幫助、無害、誠實）—— 有時候「無害」的部分意味著它要說「不」。

**常見的拒絕類型：**

| 請求類型 | 為什麼拒絕 | 改怎麼做 |
|---------|-----------|---------|
| 產生有害內容 | 安全設計 | 用合理的情境重新措辭 |
| 冒充真實人物 | 法律和倫理考量 | 用虛構角色，或要求一般性建議 |
| 醫療/法律/金融的「最終建議」 | 責任和正確性風險 | 請 Claude 解釋概念，然後去諮詢專業人士 |
| 建立登入/驗證系統 | 做不好會有安全風險 | 使用成熟的驗證服務（Auth0、Firebase Auth） |
| 非常具體的真實人物個資 | 隱私保護 | 改用公開可得的資訊 |

**如果 Claude 拒絕了合理的請求：**

有時候 Claude 太謹慎了。如果你的請求確實無害但被拒絕了：
1. 解釋情境 —— 「這是用於小說創作」或「這是為了教育目的」
2. 更具體地說明你的意圖
3. 重新措辭，讓合理的用途更明確

Claude 不是在審判你。它只是在偏向謹慎的那邊。給一點上下文通常就能解決。

## Q4：Artifacts 的作品可以直接部署成網站嗎？

**簡短答案：可以，只需要幾個額外步驟。**

| 步驟 | 做什麼 | 難度 |
|------|--------|------|
| 1 | 在 Claude 裡做好你的 Artifact | 簡單（你已經會了！） |
| 2 | 跟 Claude 說：「請給我完整的 HTML 檔案，CSS 和 JS 都內嵌」 | 簡單 |
| 3 | 把程式碼存成 `index.html` | 簡單 |
| 4 | 在瀏覽器裡打開這個檔案測試 | 簡單 |
| 5 | 部署到 Netlify Drop（拖拉放） | 簡單 |
| 6 | 完成 —— 你有一個上線的網址了 | 你現在是網頁工程師了 |

**要知道的限制：**

| 可以做 | 不能做 |
|--------|--------|
| 靜態 HTML/CSS/JS 頁面 | 伺服器端功能 |
| 瀏覽器端互動（按鈕、表單、動畫） | 資料庫連接 |
| 單頁應用程式 | 用戶驗證 |
| 任何在瀏覽器裡運行的東西 | 寄信、處理付款 |

**想做更複雜的部署**（多頁網站、資料庫等），你需要像 Vercel、Render 之類的工具，或者更傳統的 hosting 服務。但以你在這本書裡做的那些工具來說，Netlify Drop 就完美了。

詳細教學見 Ch7.7。

## Q5：Claude 跟 ChatGPT 到底差在哪？

**簡短答案：兩個都很優秀，但各有所長。**

| 面向 | Claude | ChatGPT |
|------|--------|---------|
| **開發者** | Anthropic | OpenAI |
| **最強項** | 長文件、細膩的文筆、審慎推理、Artifacts | 廣泛知識、外掛/GPTs、圖片生成 |
| **Artifacts（即時預覽）** | 有 —— 內建，非常好用 | Code Interpreter（不同的方式） |
| **寫作品質** | 更自然，比較不像「AI 味」 | 好，但有時候比較制式 |
| **執行複雜指令** | 出色 —— 處理長指令很穩 | 好，但很長的 prompt 偶爾會跑掉 |
| **圖片生成** | 無（截至 2025 年初） | 有（DALL-E 整合） |
| **外掛生態系** | Projects + Custom Instructions | 大型 GPT Store + 第三方外掛 |
| **價格** | Free / $20 Pro / $25 Team | Free / $20 Plus / $25 Team |

**結論：** 這本書用 Claude 是因為它的 Artifacts 功能、寫作品質、以及處理複雜指令的能力，讓它特別適合非開發者做工具。ChatGPT 也很棒 —— 如果你已經在用它，這本書的 Prompt 技巧可以直接轉移過去。

## Q6：我的長對話為什麼品質會下降？

**簡短答案：Context Window 的限制。**

**發生了什麼事：** Claude 有一個「Context Window」—— 它一次能考慮的文字量上限。把它想成 Claude 的短期記憶。對話越長，最早的部分就開始被擠出這個記憶窗口。

**症狀：**
- Claude「忘了」你先前給的指示
- 它開始跟 20 條訊息前說的話矛盾
- 程式碼品質下降，或它搞不清楚專案結構了
- 它問你已經告訴過它的事

**怎麼緩解：**

| 策略 | 怎麼做 |
|------|--------|
| **保持對話聚焦** | 一個主題/專案一個對話 |
| **定期摘要** | 「讓我總結一下到目前為止做了什麼：[摘要]。現在我們繼續⋯⋯」 |
| **新任務開新對話** | 不要試著把一個對話用在不相關的工作上 |
| **用 Projects** | 把持續性的背景資訊放在 Custom Instructions 裡，不要每次重複 |
| **重要指令放前面** | 把最關鍵的要求放在訊息的開頭 |

**經驗法則：** 如果一個對話超過 30-40 條訊息了，考慮開一個新的，附上目前進度的摘要。把它想成關掉一個開了 47 個分頁的瀏覽器 —— 有時候重新開始比較快。

## Q7：Claude 會「記住」我之前的對話嗎？

**簡短答案：不會。每個對話都是從零開始。**

**例外：** **Projects**（Pro 方案以上）。當你使用 Claude Projects，你可以設定在那個 Project 裡每次對話都會帶入的 Custom Instructions。但即使如此，Claude 記住的不是*對話內容* —— 是你設定的*指示*。

| 功能 | 跨對話記得嗎？ |
|------|-------------|
| 你的訊息和 Claude 的回覆 | 不會 |
| Project 裡的 Custom Instructions | 會（每次都會載入） |
| 上傳到 Project 的檔案 | 會（留在 Project 裡） |
| 偏好和寫作風格 | 只有放在 Custom Instructions 裡才會 |
| 之前做的 Artifacts | 不會（但你可以把程式碼貼回給 Claude） |

**實際操作：** 如果你做了一個很棒的東西，之後想修改它：
1. 存好程式碼（複製 HTML 或下載）
2. 開一個新對話
3. 貼上程式碼，說「這是我之前做的。我想加 [功能]。」

這是一個小小的不方便，但它讓你的對話保持新鮮，避免 Q6 提到的品質下降問題。

## Q8：我可以用 Claude 幫我做作業嗎？

**簡短答案：技術上可以，但我們不建議 —— 至少不是你想的那種方式。**

| 用法 | 判定 | 原因 |
|------|------|------|
| 「幫我寫這篇作文」 | 不好 | 你學不到東西，可能違反校規，教授通常看得出來 |
| 「解釋我不懂的概念」 | 很好 | Claude 是一個有耐心的家教 —— 叫它用不同方式解釋，直到你懂 |
| 「用這章的內容出練習題考我」 | 很好 | 用附錄 A 的 Prompt #18 來產生練習題 |
| 「檢查我的解題邏輯」 | 好 | 展示你的推導過程，問 Claude 哪裡的邏輯出了問題 |
| 「幫我擬作文大綱」 | 小心使用就 OK | 用 Claude 來腦力激盪結構，然後自己寫內容 |
| 「校對我的文章」 | 完全沒問題 | 跟用拼字檢查一樣 —— 這是工具，不是捷徑 |

**最好的用法是把它當家教：**

> 「我在學 `[主題]`，但我不懂 `[具體概念]`。可以一步一步跟我解釋嗎？解釋完之後，出一道練習題確認我真的懂了。如果我答錯了，告訴我哪裡想歪了。」

這真的是 Claude 最強大的用途之一。它是一個永遠不會不耐煩、永遠不會批判你問「笨問題」、而且凌晨兩點你恐慌複習的時候它還在線上的家教。

**道德底線：** 用 Claude 來*學得更多*，不是來*做得更少*。教育的目標是培養你自己的思考能力 —— Claude 應該放大這個過程，不是取代它。

## Q9：Claude 給的答案可以直接用在工作上嗎？

**簡短答案：可以，但你要當最後的品質把關者。**

Claude 的產出就像一個很聰明但對你公司一無所知的實習生交出來的草稿 —— 通常方向是對的，品質也不錯，但你不會不看一眼就直接交給老闆。

**驗證清單：**

| 類型 | 直接用？ | 建議 |
|------|---------|------|
| 內部溝通的 Email 草稿 | 大致可以 | 快速讀過，確認語氣和細節 |
| 客戶面對面的正式文件 | 不行 | 仔細審查內容、數據、措辭 |
| 資料分析結論 | 不行 | 抽查幾個數字，確認邏輯 |
| 程式碼 / Artifacts | 不行 | 測試功能是否正確運作 |
| 創意發想和大綱 | 可以當起點 | 加入你自己的判斷和公司脈絡 |

**核心原則：** Claude 是你的加速器，不是你的替代品。它幫你從 0 到 80% 很快，但最後那 20%（公司脈絡、人際敏感度、策略判斷）永遠是你的工作。

## Q10：免費版和付費版差在哪？

**簡短答案：免費版適合試水溫，Pro 版適合認真使用。**

| 面向 | Free | Pro ($20/月) | Team ($25/人/月) |
|------|------|-------------|-----------------|
| **使用量** | 有限（用完要等幾小時） | 大幅增加（5 倍以上） | 更多 |
| **模型** | 基本模型 | 最新、最聰明的模型 | 同 Pro |
| **Projects** | 不支援 | 支援 | 支援 + 團隊共享 |
| **檔案上傳** | 有限 | 更多 | 更多 |
| **Artifacts** | 有 | 有 | 有 |
| **隱私** | 對話可能用於訓練（可關閉） | 預設不用於訓練 | 不用於訓練 + 管理控制 |

**什麼時候該升級到 Pro：**
- 你每天都在用 Claude，免費額度經常不夠
- 你需要 Projects 來管理工作流程
- 你在處理有一定敏感度的工作內容
- 你想用最新最強的模型

**省錢建議：** 先用免費版把這本書讀完、把技巧練熟。等你發現自己每天都想用 Claude，而且免費額度是你最大的瓶頸時，再升級。那時候 $20/月 對你來說會是最划算的工具訂閱。

## Q11：AI 會取代我的工作嗎？

**簡短答案：AI 不會取代你的工作。但會用 AI 的人可能會拿走你的機會。**

（等等，這不就是 8.2 的標題嗎？沒錯，因為這個問題太重要了，值得再回答一次。）

**歷史上每一次「這次不一樣」的恐慌：**

| 年代 | 「會取代人類」的技術 | 實際發生了什麼 |
|------|-------------------|-------------|
| 1980s | 試算表 | 會計師沒消失，但不會用 Excel 的被淘汰了 |
| 1990s | Email | 秘書沒消失，但角色進化了 |
| 2000s | 搜尋引擎 | 研究員沒消失，但研究方法改變了 |
| 2010s | 智慧型手機 | 很多工作沒消失，但不會用手機的人很吃虧 |
| 2020s | AI | ??? |

看到模式了嗎？技術從來不是直接取代人。它改變的是**什麼能力是基本要求**。

**你讀完這本書之後：**
- 你已經會用 AI 來放大你的生產力
- 你理解怎麼跟 AI 協作
- 你能快速做出原型和工具
- 你有建造者心態

這些不是「會被 AI 取代」的技能。這些是「有了 AI 之後更值錢」的技能。

**真正該擔心的不是 AI，是停滯。** 只要你持續學習、持續動手做，你永遠會是有價值的人。

## Q12：我怎麼知道 Claude 的回答是不是正確的？

**簡短答案：不要盲目相信，要建立你自己的驗證習慣。**

Claude 會**很有自信地**講出不正確的東西。這叫「幻覺」(hallucination)，是目前所有 AI 模型的通病。它不是在騙你 —— 它是真的以為自己說的是對的。

**驗證的分級策略：**

| 風險等級 | 情境 | 驗證方式 |
|---------|------|---------|
| **低風險** | 創意發想、內部草稿 | 快速 sanity check，大致合理就好 |
| **中風險** | 工作報告、客戶溝通 | 查核關鍵數據和引用來源 |
| **高風險** | 專業領域（法律、醫療、財務） | 必須由專業人士驗證 |
| **最高風險** | 會影響決策的數據分析 | 抽樣驗證 + 交叉比對其他來源 |

**實用驗證技巧：**

1. **問它來源**：「你這個資訊的來源是什麼？」—— 如果它給不出具體來源，要多留意
2. **換個方式再問**：用不同的措辭問同一個問題，看答案是否一致
3. **請它自我檢查**：「請重新檢查你剛才說的，有沒有什麼不確定的地方？」
4. **交叉驗證**：重要的事用 Google 或 Perplexity 再查一次
5. **注意信心語氣**：Claude 說得越肯定的事，不代表越正確 —— 要看內容本身

**你不需要驗證每一個字。** 但你需要知道什麼時候該驗證，什麼時候可以放心。這就是「AI 素養」的核心能力。

## Q13：這本書的內容會過時嗎？

**簡短答案：操作細節會變，核心技能不會。**

AI 工具更新很快，某些功能的操作細節可能會變。但這本書教你的核心技能 — 清楚溝通、迭代修正、拆解問題 — 不會過時。我們會盡量更新內容，但如果你發現某個步驟跟書裡不一樣了，歡迎到 GitHub 回報。
