> *「我下午 4:55 上傳了一份 50 頁的季度報告。4:56 就有了一頁摘要。我準時趕上了 happy hour。Claude 是我的恩人。」*

---

PDF 無所不在。合約、報告、研究論文、產品規格書、政府法規、使用手冊。它們有一個共同點：**沒有人真的全部讀完。**

你快速掃過去。你 Ctrl+F 找關鍵字。你「打算這個週末讀」然後永遠沒有然後。不要有罪惡感——我們都一樣。

Claude 徹底改變了這件事。上傳 PDF、問你的問題、得到答案。不管那份文件是 5 頁還是 50 頁，Claude 會全部讀完，然後準確地抽出你需要的資訊。

---

## 場景 1：合約審查——找出陷阱

你收到一份 20 頁的 SaaS 廠商合約。法務團隊排到兩週後。你現在就需要知道基本的東西。

```
我上傳了一份廠商合約。請幫我：

1. 用白話中文摘要關鍵條款（不要法律術語）：
   - 合約期限和續約條件
   - 價格和付款時程
   - 我們能得到什麼（服務範圍）
   - 終止條件（怎麼解約？）

2. 標記任何「陷阱條款」——可能有問題的地方：
   - 自動續約 + 取消窗口很短
   - 價格調漲條款
   - 資料所有權（如果我們離開，誰擁有我們的資料？）
   - 看起來明顯偏一方的責任限制
   - 競業禁止或排他條款

3. 列出我簽約前「一定要」讓律師看的段落，
   附上具體的章節編號

4. 給這份合約打一個「友善度」分數，1-10 分
   （1 = 掠奪性，10 = 非常公平），並解釋原因
```

**Claude 會做什麼**：讀完整份合約，用白話中文提取關鍵條款，標記潛在的問題條款，然後給你一個務實的評估。

**重要提醒**：Claude 不是律師。這是一個初步審查，幫助你理解你在看什麼，以及跟法務討論時能問出更好的問題。不要只根據 Claude 的分析就簽約。

## 場景 2：五十頁報告做一頁摘要

你的 CEO 要你摘要一份 50 頁的產業報告。明天交。你還有三個其他的 deadline。

```
我上傳了一份 50 頁的季度產業報告。
請幫我做一份一頁的 Executive Summary，包含：

1. 關鍵發現（3-5 個重點）
   - 最重要的結論，按重要性排序

2. 市場趨勢（2-3 個重點）
   - 市場正在發生什麼變化

3. 競爭格局
   - 誰在贏、誰在輸、有沒有新的玩家

4. 風險與機會
   - 我們該擔心什麼？
   - 我們該把握什麼？

5. 建議行動
   - 根據這份報告，我們公司應該做什麼？

格式要可以直接貼到寫給 CEO 的 Email 裡。
不超過 500 字。語氣要自信、精簡——
不要「似乎」或「也許」，直接了當。
```

**Claude 會做什麼**：把 50 頁蒸餾成一份精準的、可以直接寄出的摘要。你的老闆會覺得你真的從頭到尾讀完了整份報告。（技術上來說你確實讀了——你用 AI 助手讀的。這算數。）

## 場景 3：學術論文——用小孩聽得懂的話解釋

有人分享了一篇跟你工作相關的研究論文。內容密集、術語滿天飛，讓你覺得自己翹了太多課。

```
我上傳了一篇學術論文。我不是研究人員——
我是一個（產品經理 / 行銷人 / 業務分析師）。請幫我：

1. 用一個聰明的 12 歲小孩聽得懂的話解釋主要發現
   （清楚、簡單的語言，沒有術語）

2. 告訴我「所以呢？」——我這種角色的人
   為什麼應該關心這個研究？

3. 給我 3 個具體方法，讓我可以把這些發現
   應用在日常工作中

4. 有什麼限制？研究者*沒有*證明什麼？

5. 如果我在晚餐聚會上只能用一句話解釋
   這篇論文的重點，那句話是什麼？
```

**Claude 會做什麼**：把學術寫作翻譯成白話、實用的語言。那句「晚餐聚會版」是畫龍點睛——它逼出了最濃縮的摘要。

## 場景 4：多文件比較

你可以在同一個對話裡上傳多份 PDF，讓 Claude 幫你比較：

```
我上傳了兩家廠商的提案（廠商 A 和廠商 B）。
請做一個比較表格，包含以下維度：

- 價格（三年的總成本）
- 功能覆蓋（各家提供什麼）
- 導入時程
- 售後支援和 SLA 保證
- 隱藏成本或陷阱
- 整體建議，附上理由
```

這招在你要做廠商評比的時候超級好用。不用開兩份文件左右來回翻，Claude 幫你一次看完兩份然後直接做表格。

## 文字 PDF vs. 掃描 PDF：你需要知道的差異

這很重要：

| PDF 類型 | 怎麼來的 | Claude 的處理能力 |
|----------|---------|-----------------|
| **文字 PDF** | 從 Word、Google Docs 或其他文字編輯器產生的 | 優秀——Claude 完美讀取 |
| **掃描 PDF**（圖片式） | 把紙本文件掃描產生的 | 有限——Claude 嘗試用圖像辨識讀取，品質不一定 |
| **可搜尋的掃描 PDF** | 掃描但有 OCR（光學文字辨識）層 | 不錯——Claude 可以讀 OCR 文字 |

**怎麼分辨**：打開 PDF 然後試著選取/反白文字。如果你可以選取個別的字，那就是文字 PDF。如果選取只是在整頁上畫了一個藍色方框，那就是掃描的圖片。

**如果你的 PDF 是掃描的**：
- 先試試免費的 OCR 工具（像 Adobe 的線上 OCR 或 Smallpdf）把它轉成可搜尋的文字
- 或者直接上傳，然後告訴 Claude：「這是一份掃描的文件。請盡力從圖片中讀取文字。如果有看不清楚的部分，請標記出來。」
- 你也可以把特定頁面截圖，然後上傳圖片（Claude 的圖片辨識能力相當不錯——見 4.3 節）

## 更好的 PDF 分析技巧

| 技巧 | 為什麼有用 |
|------|-----------|
| 告訴 Claude 這是什麼類型的文件 | 「這是一份法律合約」vs「這是一份技術規格書」會啟動不同的分析模式 |
| 說明你的角色 | 「我是行銷經理」幫助 Claude 調整相關性 |
| 要求附上頁碼/章節編號 | 「每個發現都附上頁碼和章節」這樣你可以去原文驗證 |
| 指定輸出格式 | 「用條列」/「用表格」/「用 Email 格式」 |
| 太長的文件分段上傳 | 如果分析看起來太淺，可能是文件太長——試試分段上傳 |
