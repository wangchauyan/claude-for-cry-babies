> *「我拍了一張在餐巾紙上畫的草圖，Claude 把它變成了一個可以用的網頁介面。我就拿著同一張餐巾紙擦眼淚。」*

---

Claude 有眼睛。而且意外地好用。

你可以上傳圖片——截圖、照片、圖表、流程圖、甚至手繪草圖——Claude 會分析、解讀、然後根據它們行動。這打開了一些近乎魔法的工作流程，特別是對那些用畫面思考、而不是用文字思考的非開發者。

---

## 場景 1：Dashboard 截圖解讀

你的數據分析團隊寄了一張 Google Analytics（或 Mixpanel 之類）的 Dashboard 截圖給你。上面滿滿的數字、圖表、趨勢線。你要在簡報裡用到這些，但你得先搞懂它們代表什麼。

上傳截圖然後說：

```
我上傳了一張我們分析 Dashboard 的截圖。
請幫我解讀：

1. 顯示了哪些關鍵指標？它們各代表什麼意思？
2. 有沒有什麼趨勢值得我在簡報中特別強調
   （正面的或令人擔憂的）？
3. 哪個指標看起來最不尋常或最值得注意？
4. 如果我要用 Dashboard 上的一個數字來開場，
   你會挑哪一個？為什麼？
5. 我的聽眾可能會問什麼問題？我應該怎麼回答？

請用非技術人員聽得懂的語言回答。
```

**Claude 會做什麼**：讀取截圖裡所有的數字、標籤和圖表。它會找出趨勢、標記異常值，然後給你可以直接用在簡報裡的 talking points。就像有一個數據分析師看著你的螢幕對你耳語：「用轉換率開場——它漲了 40%。」

## 場景 2：拍照翻譯（外文菜單、路標、說明書）

你在旅行（或同事從國外辦公室傳了照片過來），你需要讀懂一個你不會說的語言。

上傳照片然後說：

```
我上傳了一張日文餐廳菜單的照片。請幫我：

1. 翻譯每一個品項成中文
2. 加上簡短的說明（這道菜是什麼、主要食材）
3. 標記含有常見過敏原的品項
   （堅果、海鮮、麩質、乳製品）
4. 推薦 3 道適合第一次吃日本料理的人的菜
```

**Claude 會做什麼**：從圖片中讀取文字、翻譯、加上背景資訊、甚至給推薦。這同樣適用於：外語的產品標籤、外國同事手寫的筆記、外文軟體的截圖等等。

## 場景 3：手繪草圖變真的介面

這是讓人下巴掉下來的那一招。

在紙上（或白板上、或喝了兩杯之後的餐巾紙上）畫一個粗略的 UI 草圖。拍照。上傳。

```
我上傳了一張我手繪的 App 介面草圖。請幫我：

1. 先描述你在草圖中看到什麼
   （讓我確認你理解對了）
2. 把這個草圖做成一個真正可以互動的 Artifact，
   盡可能貼近草圖的排版
3. 用乾淨、現代的設計風格
4. 所有的按鈕和互動元素都要真的能用
   （哪怕只是彈出一個提示或改變狀態）
5. 草圖上我畫了但沒標清楚的文字區域，
   幫我填上合理的 placeholder 文字
```

**Claude 會做什麼**：解讀你的手繪線框稿、確認它的理解、然後生成一個可以點擊的互動版本。你的餐巾紙塗鴉變成了一個可以 demo 的原型。

**讓草圖辨識更好的技巧**：
- 用深色筆在白紙上畫（對比度很重要）
- 盡可能標註元素（「搜尋欄」、「選單」、「大頭照」）
- 方框和線條畫清楚——亂一點沒關係，但可辨識的形狀有幫助
- 在光線充足的地方拍照，鏡頭正對紙面（不要斜角）

### 草圖到原型的完整工作流程

這其實是一個正式的產品設計技巧。完整的流程：

```
1. 在紙上畫草圖（2 分鐘）
2. 拍照 + 上傳到 Claude（30 秒）
3. Claude 生成互動原型（30 秒）
4. 用後續的 prompt 調整（5-10 分鐘）
5. 把原型秀給你的團隊看，拿回饋（無價）
```

總時間：從餐巾紙到可點擊的原型大約 15 分鐘。跟打開 Figma 然後花一整個下午相比⋯⋯。對早期階段的概念驗證來說，這個方法無敵。

## 場景 4：錯誤截圖疑難排解

螢幕上出現一個看不懂的錯誤訊息？截圖上傳：

```
我的螢幕上出現了這個錯誤。我不懂技術——
請告訴我：

1. 這個錯誤用白話說是什麼意思
2. 可能是什麼原因造成的
3. 我應該怎麼一步一步修復
4. 我需要擔心資料遺失或安全問題嗎？
```

適用於：軟體錯誤、安裝失敗、瀏覽器錯誤頁面、系統通知，還有你的印表機一直顯示的那個神秘訊息。

## 圖片上傳的 Pro Tips

| 技巧 | 為什麼 |
|------|--------|
| **用清晰的高解析度圖片** | 模糊的圖片 = 模糊的分析。Claude 需要能讀文字、看到細節 |
| **裁切到你關心的區域** | 不要上傳整個桌面——裁到圖表、錯誤訊息、或你在意的部分 |
| **一次一張** | 一次上傳一張截圖配一個問題。一封訊息放太多圖片會分散焦點 |
| **告訴 Claude 它在看什麼** | 「這是我們 Salesforce Dashboard 的截圖」提供了重要的上下文 |
| **標記你感興趣的區域** | 用手機/電腦的畫筆工具，在你想問的部分畫一個紅圈 |
| **說明你已經試過什麼** | 「我已經重啟了 App」幫 Claude 跳過基礎建議 |

## Claude 能看到什麼、不能看到什麼

| 看得清楚的 | 比較吃力的 |
|-----------|-----------|
| 印刷文字 | 非常小或低對比度的文字 |
| 圖表和趨勢圖 | 元素重疊的 3D 圖表 |
| UI 排版和線框稿 | 極度複雜的技術架構圖 |
| 手寫字（如果夠清楚的話） | 醫生等級的手寫字（抱歉了各位醫師） |
| 物品和場景照片 | 非常暗或加了很多濾鏡的照片 |
| 表格和結構化數據 | 嚴重壓縮的 JPEG 雜訊 |
| 顏色和設計元素 | 從截圖精確讀取色碼（hex code） |
