> *「知道你的魔法棒不能做什麼，比知道它能做什麼更重要。不然你會花兩小時試圖讓它召喚一條龍。」*

---

Artifacts 很強，但它不是無限的。在你試圖用 Artifacts 做出下一個 Instagram 之前，讓我們誠實地聊聊它的邊界在哪裡。現在把期待值校準好，會幫你省下大量的挫折感。

限制不是一張「失敗清單」，而是一張**邊界地圖**。知道邊界在哪，你才能在安全區域裡蓋出最厲害的東西。

---

## 七面牆：Artifacts 的硬限制

| 限制 | 白話翻譯 | 舉例 | 替代方案 |
|------|---------|------|---------|
| **不能呼叫外部 API** | Artifacts 住在一個沙盒裡，不能連到外面的網路世界 | 不能即時抓台積電股價、不能連 OpenWeather 顯示天氣、不能串接社群媒體動態 | 手動把數據丟給 Claude，讓它生成靜態圖表 |
| **有限的儲存能力** | 可以用內建的儲存 API 存一些簡單的 key-value 資料，但別把它當資料庫 | 簡單的設定值可以存；但你的待辦清單在你清快取之後可能就消失了 | 加一個「匯出」按鈕，把資料複製到剪貼簿或下載成檔案。**把 Artifacts 當暫時性工具** |
| **沒有後端 / 伺服器** | 背後沒有一台電腦在替你跑程式、存資料 | 不能做會員登入、不能儲存表單提交紀錄、不能處理付款 | 用 Artifacts 做前端原型，真正需要後端時再找工程師或用 no-code 工具 |
| **複雜度天花板（約 500 行）** | 太大太複雜的應用程式會開始當機、變慢、或顯示不正常 | 一個完整的專案管理系統大概跑不動 | 把大專案拆成多個小 Artifacts，每個負責一個功能 |
| **不能存取你的檔案系統** | 不能讀取或寫入你電腦上的檔案 | 不能自動存檔到你的桌面、不能讀取你的本機資料 | 用「複製到剪貼簿」或「下載」功能手動處理 |
| **有限的第三方套件** | 能用一些常見的函式庫，但不是什麼都有 | 某些特殊的圖表庫或動畫庫可能用不了 | 用 Artifacts 內建支援的套件（React、Recharts 等），或跟 Claude 確認哪些可以用 |
| **綁定在對話裡** | 每段對話是獨立的世界，不能跨對話帶東西過去，也不能主動推送更新 | 你星期二做的心情追蹤器，星期三開新對話就不在了 | 做出滿意的成品後，立刻複製程式碼保存起來 |

## Artifacts 最適合做什麼？

知道了不能做的，來看看它真正大放異彩的場景：

| 使用場景 | 為什麼特別適合 | 範例 |
|---------|--------------|------|
| **計算機 / 轉換器** | 單一功能、不需要存資料、即開即用 | 匯率計算機、BMI 計算器、單位轉換器 |
| **產生器** | 填入資訊就能產出格式化的內容 | 週報產生器、合約模板、社群貼文產生器 |
| **資料視覺化** | 把數字變成圖表，一眼看出趨勢 | 月營收趨勢圖、問卷結果分析、專案進度圖 |
| **學習 / 教學工具** | 把抽象概念變成可以點擊互動的東西 | 互動式時間軸、可點擊的人體解剖圖、數學公式視覺化 |
| **原型 / 概念驗證** | 在投入真正開發之前，先看看這個想法長什麼樣子 | 「這個 Dashboard 的版面配置好不好看？」 |
| **簡報 / 視覺素材** | 快速做出會議和提案需要的圖表 | 組織架構圖、流程圖、功能比較表 |
| **遊戲 / 測驗** | 小型互動內容，不需要存進度 | 性格測驗、知識問答、猜謎遊戲 |

## 決策框架：該不該用 Artifacts？

當你猶豫「這個東西該不該用 Artifacts 做？」的時候，跑一次這個決策樹：

```
這個東西是...
  ├── 一頁就能搞定？ → 大概可以，做吧
  ├── 需要永久存資料？ → 不太適合，考慮其他工具
  ├── 需要即時的網路資料？ → 不行，Artifacts 連不了外網
  ├── 只是想試試看一個想法？ → 完美場景，衝吧
  ├── 需要很多頁面 / 路由？ → 可能會很掙扎
  └── 在開會時展示用的？ → 超級適合，就是這個
```

簡單來說：**如果你的目標是「快速把腦袋裡的想法變成可以看、可以點的東西」，Artifacts 就是你的最佳夥伴。** 如果你的目標是「做一個每天幾千人用的正式產品」，那你需要的是真正的開發。

## 週報產生器 v0.3

還記得我們的週報產生器嗎？在第 1 章，它只是一段 prompt 模板。在第 2 章，我們用溝通技巧把它打磨得更精準。現在，是時候讓它**真正活起來**了 — 變成一個有介面、可以互動的工具。

把這段 prompt 複製貼上給 Claude：

```
請用 React Artifacts 幫我做一個互動式的週報產生器，要有以下功能：

版面配置：
- 左右分欄（手機版改成上下排列）
- 左邊是「輸入區」
- 右邊是「即時預覽區」（隨著我打字即時更新）

輸入區的欄位：
1. 「你的名字」- 文字輸入框
2. 「週次」- 日期選擇器（預設為本週）
3. 「本週完成事項」- 大文字框（placeholder：「列出本週完成的工作，每行一項」）
4. 「進行中的工作」- 大文字框（placeholder：「目前正在進行什麼？」）
5. 「遇到的困難」- 文字框（placeholder：「有什麼卡住的地方或需要幫忙的？沒有就留空」）
6. 「下週計畫」- 文字框（placeholder：「下週打算處理什麼？」）
7. 「本週亮點 & 感謝」- 文字框（placeholder：「團隊的好消息或想感謝的人？選填」）

預覽區：
- 隨著左邊輸入即時更新，顯示格式化的正式週報
- 報告格式要有：
  - 標題區（名字 + 週次日期）
  - 各區塊用清楚的標題分隔
  - 完成事項和進行中的工作自動轉成項目符號列表
  - 如果「遇到的困難」有填寫，用橘黃色的醒目區塊標示
  - 底部有一行小字 "Generated with Weekly Report Generator"
- 預覽的樣子要像一份你真的會寄給主管的正式報告

額外功能：
- 「複製為 Markdown」按鈕：把格式化的報告複製到剪貼簿
- 「清除全部」按鈕：重置所有欄位
- 「填入範例」按鈕：用範例資料填滿所有欄位，讓使用者一眼看出效果
- 配色用莫蘭迪色系（柔和的灰綠 + 米白 + 暖灰），整體風格要像一個專業的 SaaS 產品，不是學生作業
```

**你應該會看到什麼：** 一個真正可以用的工具。在左邊打你這週做了什麼，右邊即時出現一份排版漂亮的週報。按下「複製為 Markdown」，貼到 Slack、Email、或你公司的週報系統裡。

這不是玩具。這是一個你每個星期五下午可能真的會用到的工具。而你做出它的方式，就是用人話描述你要什麼。

### v0.3 教了你什麼

| 學到的技巧 | 對應的 prompt 手法 |
|-----------|-------------------|
| 左右分欄的版面配置 | 「左右分欄（手機版改成上下排列）」 |
| 即時更新的預覽 | 「隨著我打字即時更新」 |
| 預設值 | 「預設為本週」 |
| Placeholder 引導使用者 | 每個欄位都有具體的 placeholder 文字 |
| 多個不同功能的按鈕 | 複製、清除、填入範例 |
| 專業的視覺風格 | 「莫蘭迪色系」「像一個專業的 SaaS 產品」 |

### v0.3 加分挑戰

如果你覺得意猶未盡，試試這些追加 prompt：

```
「在每個文字框下面加上字數統計」
```

```
「加一個切換鈕，可以在『詳細版』和『摘要版』之間切換。
摘要版只顯示每個區塊最重要的重點，不要廢話。」
```

```
「加一個『語氣』下拉選單（選項：專業正式、輕鬆日常、熱情積極），
選擇後預覽區的用詞和格式會跟著調整。」
```

## 第三章完整回顧

你從「Artifacts 是什麼？」走到了親手做出三個互動專案。來回顧一下這趟旅程：

| 學會的技能 | 在哪裡學的 |
|-----------|-----------|
| 理解 Artifacts 是什麼（以及不是什麼） | 3.1 節 |
| 用正確的語言觸發 Artifacts | 3.2 節 |
| 迭代式建構模式（基礎 → 打磨 → 擴展） | 3.3 節 — 心情選擇器 |
| 用人話描述視覺設計 | 3.4 節 — 個人名片 |
| 從數據做出圖表 | 3.5 節 — 資料視覺化 |
| 認識 Artifacts 的限制，在邊界內發揮最大價值 | 3.6 節 — 就是這裡 |

**這章最大的收穫：** Artifacts 是你的原型超能力。它不是東西最終住的地方，但它是想法第一次變成「真的」的地方。對一個非工程師來說，那個瞬間 — 看著你的文字變成可以點擊、可以互動的東西 — 真的有一點魔法的感覺。

就算你感動到掉了幾滴眼淚也沒關係。我們都是哭包嘛。
