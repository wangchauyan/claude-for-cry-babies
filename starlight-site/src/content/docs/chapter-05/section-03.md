以下是三個你在用 Claude 做東西的時候，幾乎一定會遇到的真實錯誤。每一個我都會告訴你：它長什麼樣、白話翻譯是什麼意思、以及你可以直接複製貼上的修復 Prompt。不需要任何程式知識。照做就對了。

## Case 1：React 元件沒有 default export

### 你會看到什麼

預覽面板出現紅色錯誤訊息：

```
Error: The default export is not a React Component
  in page "/page"
```

或者有時候長這樣：

```
Element type is invalid: expected a string or a class/function
but got: undefined
```

### 白話翻譯

想像你寫了一本食譜。封面寫著「第一章：巧克力蛋糕」。但翻到第一章的時候，頁面是空白的 -- 或者更慘，裡面放的是魚塔可的食譜。目錄承諾了一件事，內容卻給了另一件（或什麼都沒給）。

這個錯誤就是這樣。Claude 創建了一個檔案，告訴系統「這裡有一個叫 MyApp 的元件」，但系統打開一看，要嘛找不到 MyApp，要嘛找到的東西根本不像一個合格的元件。通常是 Claude 忘了「匯出」那個元件 -- 就像寫了一篇很棒的作文，但交卷的時候忘了寫名字。

### 修復 Prompt

```
出現了這個錯誤：
"The default export is not a React Component"

這通常代表元件沒有被正確匯出。
請檢查主要的元件檔案，確保：
1. 有正確的 "export default" 語句
2. 元件函數回傳了有效的 JSX
3. 函數名稱跟匯出的名稱一致

請修復匯出，並保留所有現有功能不變。
```

### 為什麼這樣有效

你給了 Claude 三個具體的檢查項目，用白話文寫。你不需要知道「JSX」或「export default」是什麼 -- Claude 知道就好。你基本上是在說：「嘿，你的目錄和你的內容對不上，去把連接修好。」

## Case 2：CSS 跑版（排版亂掉）

### 你會看到什麼

沒有任何錯誤訊息。App「能用」。但排版看起來像被龍捲風掃過：

- 元素垂直堆疊，但它們應該要並排
- 文字溢出容器外面
- 所有東西擠在左上角
- 手機上看的時候元素互相重疊，完全看不清
- 按鈕躲在另一個元素後面

### 白話翻譯

這是一個家具擺放問題。Claude 把所有正確的家具都搬進房間了，但沙發擋住了門、電視面對牆壁、餐桌不知道怎麼跑到天花板上去了。東西都在 -- 只是位置全部亂掉了。

### 修復 Prompt

修排版問題的關鍵是**空間描述要具體**。說「看起來不對」不會有什麼幫助。描述排版就像你在指路一樣：

**爛 Prompt：**
```
排版壞了，修一下。
```

**好 Prompt：**
```
排版需要修正。以下是我需要的配置：

頂部區塊：全寬橫跨頂端，固定不動（捲動時保持可見）

主要內容區：兩欄並排
- 左欄（30% 寬度）：導航選單、項目列表
- 右欄（70% 寬度）：詳細內容/顯示區域

底部區塊：全寬在最底端

目前的問題：所有東西都垂直堆疊在一個欄位裡。
導航選單和內容區應該是「並排」的，
不是上下疊在一起。

手機版（小螢幕）可以堆疊，但桌面版必須並排。

請修正排版，保留所有現有功能不變。
```

### 排版用語速查表

你不需要會 CSS，但這些白話用語能幫助 Claude 理解你的空間意圖：

| 你想要的效果 | 怎麼描述 |
|-------------|---------|
| 東西並排 | 「兩欄並排」或「水平排列」 |
| 東西上下疊 | 「垂直堆疊」或「一個在另一個上面」 |
| 頁面置中 | 「水平垂直都置中在頁面上」 |
| 固定在頂端 | 「固定在頂端，捲動時保持可見」 |
| 項目之間有間距 | 「每個項目之間加上間距/gap」 |
| 等寬項目 | 「每個項目佔相同寬度」 |
| 響應式 | 「手機版垂直堆疊，桌面版並排」 |
| 東西被遮住 | 「[元素 A] 被 [元素 B] 擋住了，把 A 移到前面」 |

## Case 3：功能只做了一半

### 你會看到什麼

你要求了一個有三個部分的功能，Claude 只做了兩個。或者它做了 UI（表單、按鈕）但沒有做背後的邏輯。App 做了你要求的*一部分*，但悄悄忽略了其餘的。

### 白話翻譯

你請裝潢師傅幫你做一間浴室，要有洗手台、馬桶和淋浴間。他裝好了漂亮的洗手台和馬桶，說了一聲「搞定！」就走了。淋浴間？什麼淋浴間？他要嘛忘了、要嘛做到一半上下文用完了、要嘛覺得太複雜就假裝沒這回事，賭你不會注意到。

（你注意到了。）

### 修復 Prompt

關鍵是：明確指出「少了什麼」，同時**不要讓 Claude 動到已經做好的部分**。這就像告訴裝潢師傅：「回來裝淋浴間，但看在老天的份上，不要碰馬桶。」

**補完 Prompt：**

```
目前版本部分完成了。以下是已完成和未完成的部分：

已完成（請勿修改）：
- 輸入表單的所有欄位（名稱、日期、項目）-- 運作正常
- 樣式和排版 -- 看起來很好
- 儲存按鈕 -- 能正確存到列表

未完成（請補上）：
- 刪除按鈕：列表中每個項目應該有一個小 "X" 按鈕，
  點擊後移除該項目
- 編輯功能：點擊項目後可以直接在行內編輯。
  編輯完按 Enter 儲存修改。

請「只」新增缺少的功能。不要改動樣式、排版
或現有功能的行為。
```

**為什麼「請勿修改」這句話至關重要：**

如果你不明確保護已完成的部分，Claude 可能會：
- 在加功能的同時「順便」重構整個程式碼（然後搞壞東西）
- 為了配合新功能而改掉排版
- 用一個「更好」的版本取代你精心調整過的元件，然後你的客製化全部消失

明確告訴 Claude 什麼不要動，就像在所有做好的東西上貼「油漆未乾 -- 請勿觸摸」的告示牌。Claude 會尊重界線 -- 但你得先把界線畫出來。

## 萬用修復 Prompt 模板

收藏這些。使用這些。愛上這些。

### 模板 1：錯誤訊息修復
```
出現了這個錯誤：[貼上錯誤訊息]
預期行為：[應該發生什麼]
實際行為：[實際發生了什麼]
請修復，同時保持所有現有功能正常運作。
```

### 模板 2：排版修復
```
排版需要修正：
- [元素 A] 應該要 [位置/大小]
- [元素 B] 應該要 [位置/大小]
目前的問題：[描述空間上哪裡不對]
修正排版的同時保持所有功能不變。
```

### 模板 3：缺少功能
```
已完成的功能（不要動）：[列出來]
缺少的功能（請補上）：[詳細列出]
只新增缺少的功能，不要修改已完成的。
```

## 什麼時候該砍掉重練 vs. 繼續修

這是一個很多人會卡住的決定。你已經跟 Claude 來回了十幾輪，東西改來改去，好像越改越亂。這時候你會問自己：「我是該繼續修，還是打掉重來？」

### 沉沒成本陷阱

先說一個殘酷的事實：**你跟 Claude 對話了二十輪不代表你應該繼續對話下去。**

這叫沉沒成本謬誤（Sunk Cost Fallacy）。你花了時間，所以捨不得放棄。但那些時間已經花了，不管你繼續還是重來，那些時間都回不來了。

你應該問的不是「我已經投入了多少時間？」而是「從現在這個狀態出發，繼續修比較快，還是重新開始比較快？」

### 你的對話正在原地打轉的五個跡象

1. **Claude 開始重複之前的錯誤** -- 你修了 A，它把 B 改壞了。你修了 B，它又把 A 改回去。無限迴圈。
2. **每次修改都產生新的問題** -- 像打地鼠一樣，按下這個，跳出那個。
3. **Claude 開始說「對不起」超過三次** -- 當它開始頻繁道歉但問題依然存在，代表它的上下文已經混亂了。
4. **你已經看不懂 Claude 在改什麼了** -- 如果連你都搞不清楚現在跟上一版差在哪裡，Claude 更搞不清楚。
5. **整個對話已經超過 20 輪** -- 長對話會讓 Claude 的「注意力」分散，它會忘記前面的指令。

### 砍掉重練的正確方式：「帶著經驗重新開始」

重新開始不代表前功盡棄。你在前一輪對話中學到了什麼是 Claude 容易搞錯的、什麼是你真正想要的。把這些濃縮成一個更好的起始 Prompt：

```
[新對話]

我要做一個 [工具名稱]。我之前試過一次，
以下是我學到的重點：

必須包含的功能：
1. [功能 A] -- 上次做對了，保持這個方式
2. [功能 B] -- 上次用了 XX 方法但有問題，
   請改用 YY 方法
3. [功能 C] -- 這是上次漏掉的，這次一定要有

上次遇到的問題（請避免）：
- [問題 1 的描述]
- [問題 2 的描述]

請一次生成完整版本。
```

你不是從零開始 -- 你是帶著全部的經驗值從一開始。這就是為什麼第二次嘗試幾乎總是比第一次好得多。
