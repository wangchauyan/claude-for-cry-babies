---
title: "5.1 報錯的三種類型（非工程師版）"
---


當你的 Artifacts 或 Claude 的輸出「出問題」時，通常是以下三種情況之一。

## 類型 1：看得到但點不動

**症狀**：Artifacts 畫面出來了，長得也不錯，但按鈕按下去沒反應，輸入框打不了字。

**白話翻譯**：Claude 畫好了外殼，但忘了裝引擎。

**常見原因**：
- 事件處理（Event Handler）沒有正確綁定
- 某個函數名字打錯了

**你不需要理解上面那些技術名詞。** 你只需要知道：這是最容易修的一種。

## 類型 2：畫面爆炸

**症狀**：Artifacts 面板顯示一片紅字錯誤訊息，或者什麼都沒顯示。

**白話翻譯**：Claude 寫的程式碼有語法錯誤，就像一篇文章裡有錯字，整篇就讀不通了。

**常見原因**：
- 少了一個括號或逗號
- 用了不支援的語法
- 元件引用方式錯誤

**感覺很可怕？別擔心，接下來教你怎麼修。**

## 類型 3：驢唇不對馬嘴

**症狀**：沒有報錯，畫面也正常，但做出來的東西根本不是你要的。

**白話翻譯**：Claude 理解錯了你的需求，或者它理解了但能力不夠。

**常見原因**：
- 你的 prompt 不夠具體
- Claude 對你的需求做了錯誤的假設
- 需求太複雜，Claude 只完成了一部分

**這種情況最常見，也最容易解決 — 回到第 2 章的溝通技巧就好。**

---

## 判斷流程

```
出問題了！
    │
    ├─ 有紅色錯誤訊息嗎？ ──→ YES ──→ 類型 2：複製錯誤訊息丟回去
    │                        │
    │                        NO
    │
    ├─ 功能能正常操作嗎？ ──→ NO ───→ 類型 1：描述哪個功能壞了
    │                        │
    │                        YES
    │
    └─ 結果是你要的嗎？ ───→ NO ───→ 類型 3：重新描述你的需求
                             │
                             YES ──→ 恭喜，沒問題！🎉
```
