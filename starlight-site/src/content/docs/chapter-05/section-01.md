> *「我不知道哪裡壞了，但我知道一定有東西壞了。我是不是該去補修資工系？」*

---

不用。你只需要學會辨認三種 pattern。就三種。如果你能分辨「瓦斯爐打不著」、「瓦斯爐著火了」跟「瓦斯爐自己煮出了一鍋你沒點的酸辣湯」，你已經具備所有需要的技能了。

來，認識一下我們的三個麻煩製造者。

---

## 類型 1：已讀不回型

**症狀**：Artifacts 畫面出來了，長得也不錯，顏色對、排版美、一切看起來很正常。但你按下按鈕... 什麼事都沒發生。表單送出去像石沉大海。下拉選單就靜靜地躺在那裡，純裝飾用。

**白話翻譯**：Claude 幫你造了一台外觀超帥的跑車，但忘了裝引擎。烤漆完美、線條流暢，就是開不了。

**為什麼會這樣**：Claude 生成了視覺結構（HTML/CSS），但忘了接上邏輯（JavaScript）。就像開了一家餐廳，菜單印得很精美，但廚房沒有請廚師 -- 每道菜看起來都很好吃，就是沒人在煮。

**怎麼發現它**：
- 按鈕按下去毫無反應
- 表單填完送不出去
- 下拉選單打得開，選了之後什麼效果都沒有
- 「計算」按鈕計算了一個寂寞
- 整個頁面基本上是一張非常逼真的 App 截圖

**真實案例**：
你請 Claude 做一個小費計算機。它生成了一個漂亮的表單，有「帳單金額」和「小費百分比」的輸入框，還有一個大大的綠色「計算」按鈕。你輸入 $50 和 20%，按下計算... 總金額的欄位依然空白。那顆按鈕盡了它最大的努力扮演一個裝飾品。

---

## 類型 2：爆炸型

**症狀**：Artifacts 面板顯示一片紅字錯誤訊息，或者什麼都沒顯示 -- 一片慘白。看起來很恐怖，而且它完全不打算低調。

**白話翻譯**：這是語法錯誤 -- Claude 打了一個錯字。不是人類那種「的地得」用錯的錯字，而是程式碼層面的 typo。可能少了一個括號、多了一個逗號、或是某個函數名字拼錯了。一個小小的字元放錯位置，整個東西就罷工了。就像你打電話少撥了一碼，就接到了一個完全陌生的人。

**怎麼發現它**：
- 畫面上出現紅色錯誤文字（有時候還會被框起來，看起來更嚇人）
- 本該出現你的 App 的地方變成一片白
- 出現「Error」、「undefined」、「null」或「unexpected token」這些字眼
- Claude 的預覽面板直接說「Something went wrong」

**真實案例**：
你請 Claude 加一個深色模式切換鈕。結果預覽畫面突然一片空白，只剩一行小小的紅字：`SyntaxError: Unexpected token '<'`。看起來超嚇人，但它真的就只是一個放錯位置的字元。就像 Claude 打字的時候打了個噴嚏。

---

## 類型 3：驢唇不對馬嘴型

**症狀**：沒有報錯。沒有白屏。一切正常運作。按鈕能按、表單能送。只有一個小小的問題：**它做的不是你要的東西。**

**白話翻譯**：Claude 聽懂了你的每一個字，但沒聽懂你的意思。你要一個「銷售儀表板」，它給你一個顯示天氣資料的儀表板。功能完美 -- 只是完美地做了錯誤的事。

想像一下你用 Google Maps 導航：你說要去「天母 SOGO」，它帶你去了「忠孝 SOGO」。GPS 確實帶你到了一個 SOGO，路線也完全正確，只是... 到錯地方了。這就是「自信地做錯事」。

**為什麼會這樣**：你的指令有模糊的地方，或者 Claude 做了錯誤的假設。這是三種類型裡最棘手的，因為技術上什麼都沒壞 -- 壞的是你想要的和 Claude 以為你想要的之間的落差。

**怎麼發現它**：
- 計算結果是錯的
- 排版跟你描述的不一樣
- 有些功能不見了，或者多了你沒要求的功能
- 語氣或風格完全不對
- 按下去有反應，只是... 不是你期望的反應

**真實案例**：
你要求「按優先順序排列清單」，Claude 幫你按字母順序排了。技術上確實是排序了！只是不是按優先順序。因為你沒有定義「優先」在你的情境裡是什麼意思，Claude 就自己猜了一個。

## AI 犯錯的四大類型

在更深入之前，讓我們聊聊 AI 到底是「怎麼」犯錯的。理解這個，你就能更快抓到問題出在哪裡：

### 1. 自信滿滿地搞錯（Confidently Wrong）

Claude 用非常篤定的語氣告訴你一個完全錯誤的答案。它不會說「我不確定」，它會直接給你一個看起來很合理但其實是胡扯的回答。

這就像問路遇到一個超級熱心的路人，他非常自信地指了一個方向，你走了二十分鐘才發現他指反了。他不是故意的，他是真心覺得自己知道。

### 2. 對了一半（Partially Right）

更危險的情況：Claude 給你的答案有七成是對的，但混了三成的錯誤。因為大部分是對的，你很容易就全盤接受了。

就像一份考卷改到 70 分就停了，剩下的答案它用猜的，但語氣跟前面那些確定的答案一模一樣。

### 3. 過時資訊（Outdated Info）

Claude 的知識有截止日期。如果你問它最新的工具版本或最近的事件，它可能會給你舊的答案，但用現在式講出來，讓你以為那是最新的。

### 4. 理解錯任務（Misunderstood Task）

你以為你說得很清楚了。Claude 也以為它聽懂了。結果你們兩個在平行宇宙裡各自努力。這通常發生在指令太模糊，或者你假設 Claude 知道某些背景但其實它不知道。

---

## 偵測策略：像 GPS 一樣思考

分辨錯誤類型有一個很好的比喻：**GPS vs. 喝醉的朋友**。

**GPS 導航**是你的理想狀態：
- 它會明確告訴你「前方 500 公尺右轉」
- 走錯路了，它會重新計算路線
- 它不會假裝知道不知道的事

**喝醉的朋友**是你不想遇到的：
- 「就那邊啊，很近很近」（模糊且不準確）
- 走錯了不會告訴你，因為他自己也不知道
- 非常有自信，信心跟正確率完全不成正比

你要做的就是讓 Claude 更像 GPS，少像喝醉的朋友。怎麼做？**主動要求它說明推理過程**。如果它能清楚解釋「為什麼」這樣做，通常答案是對的。如果它的解釋含糊不清或前後矛盾，紅旗就升起來了。

## 判斷流程

遇到問題時，照著這個流程走：

```
出問題了！
    │
    v
頁面有沒有紅色錯誤訊息？
    │
    ├─ YES ──→ 類型 2：爆炸型
    │           動作：截圖那些紅字，
    │           丟回給 Claude 說「修這個錯誤」
    │
    ├─ NO
        │
        v
    按鈕/表單/互動功能按了有反應嗎？
        │
        ├─ NO ──→ 類型 1：已讀不回型
        │          動作：告訴 Claude 哪個按鈕/功能
        │          沒有反應。「[X] 按鈕按了沒反應，
        │          請補上邏輯。」
        │
        ├─ YES
            │
            v
        輸出/行為是你真正想要的嗎？
            │
            ├─ NO ──→ 類型 3：驢唇不對馬嘴型
            │          動作：描述它「現在做了什麼」
            │          vs.「應該做什麼」。
            │          「按 X 的時候它做了 Y，
            │          但我需要它做 Z。」
            │
            ├─ YES ──→ 沒問題！去慶祝吧！
```

## 速查表

| 類型 | 症狀 | 比喻 | 修復方式 |
|------|------|------|---------|
| **已讀不回** | 看起來正常，沒有反應 | 漂亮跑車，沒裝引擎 | 「請幫 [功能] 補上邏輯」 |
| **爆炸** | 紅字錯誤、白屏 | 一個 typo 毀了全部 | 截圖 +「修這個錯誤」 |
| **驢唇不對馬嘴** | 能用，但結果是錯的 | GPS 帶你去錯的城市 | 「它做了 X，但我需要 Y」 |

好消息？三種都能修。而且修復的過程幾乎都是一樣的三個步驟，我們下一節就會教。
