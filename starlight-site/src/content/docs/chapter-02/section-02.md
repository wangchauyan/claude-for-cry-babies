---
title: "2.2 五個真實場景的 Prompt 改造術"
---


> *「從理論學 prompt 就像從教科書學做菜。你需要看真的人在真的廚房裡煮飯。」*

---

以下五個場景，都是真實上班族每週都在做的事情。每個場景都包含 Before（菜鳥版）和 After（進化版），以及為什麼差這麼多。仔細看差異，偷走裡面的模式。

---

## 場景 1：寫一封請假信

### ❌ 菜鳥版

```
幫我寫請假信。
```

**結果**：Claude 給你一封萬用模板，語氣像在寫給聯合國秘書長。「敬啟者，本人謹此申請⋯⋯」——放在 2005 年的 HR 培訓手冊裡毫無違和感。

### ✅ 進化版

```
請幫我寫一封跟直屬主管請假的 Email。細節如下：

- 收件人：我的主管 Rachel（我們很熟，合作兩年了）
- 日期：5/5 到 5/9（整週）
- 原因：搬家。我知道不是什麼偉大的理由，
  不用花太多篇幅解釋
- 代理安排：我已經請 Tom 處理客戶電話，
  Q2 報告我會在走之前完成
- 語氣：溫暖但專業，不用太正式
- 長度：簡短——Rachel 每天看 200 封 Email，
  她會感謝你的簡潔

請加上主旨行。
```

**結果**：一封自然流暢的 Email，Rachel 30 秒內就會批准，因為她所有的問題都被提前回答了。

**可以偷的模式**：告訴 Claude *關係動態*（我們很熟）和*讀者的限制*（Rachel 很忙）。

## 場景 2：分析一份銷售報表

### ❌ 菜鳥版

```
分析這個銷售數據。
```
*（上傳一個 CSV 檔）*

**結果**：一堆顯而易見的觀察。「三月的營收高於二月。」謝啦 Claude，真是開創性的發現。

### ✅ 進化版

```
我上傳了我們的 Q1 銷售數據（CSV 檔）。我明天要跟
業務總監報告。請用以下目標分析：

1. 找出營收和成長率分別最好的前 3 個產品
   （這兩個可能是不同產品——這才是有趣的地方）
2. 標記任何月銷售額下滑超過 15% 的產品——
   我在會議上需要解釋原因
3. 比較各區域表現：北區 vs 南區 vs 中區
4. 做一個摘要表格，讓我可以直接貼到簡報裡

背景：我們二月推出了新的定價方案。
總監一定會想知道效果怎麼樣。

格式：先給我三句話的 Executive Summary，
然後才是詳細分析和表格。
```

**結果**：一份讓你看起來像花了三小時做 Excel 分析的報告（你其實只花了三分鐘）。

**可以偷的模式**：告訴 Claude *業務背景*（新定價方案）和*聽眾可能會問的問題*（效果好不好？）。

## 場景 3：做一個生日邀請函網頁

### ❌ 菜鳥版

```
做一個生日邀請的頁面。
```

**結果**：一個技術上可以運作但醜到不行的網頁，看起來像 1997 年做的。Comic Sans 字體可能有也可能沒有出現。

### ✅ 進化版

```
請用 Artifacts 做一個生日派對邀請函的單頁網頁。

細節：
- 我女兒小美的 5 歲生日
- 日期：6 月 14 日星期六，下午 3 點
- 地點：信義區的 Doodle Land 兒童樂園
- 主題：獨角獸派對——夢幻但不俗
- 配色：粉紫色 + 金色
- 包含：頁面載入時有彩色碎紙片的動畫效果
- 包含：派對倒數計時器
- 包含：「請穿粉色系或彩虹色系出席！」
- 包含：RSVP 區塊，寫上「請私訊小美媽咪報名」
- 氛圍：像迪士尼公主開了一場 house party

字體要圓圓可愛的。不要用新細明體，謝謝。
```

**結果**：一個讓你驕傲到想分享到家長群組的網頁。倒數計時器和碎紙片動畫是零技術知識就得到的加分細節。

**可以偷的模式**：給*視覺和情感方向*（配色、氛圍）。「像迪士尼公主開了一場 house party」這種描述，比任何技術規格都讓 Claude 更有靈感。

## 場景 4：整理會議記錄

### ❌ 菜鳥版

```
整理一下這個會議紀錄。
```
*（貼上一大片混亂的筆記）*

**結果**：同樣的內容，稍微重新排版。可能加了一些 bullet points。基本上是高級版的複製貼上。

### ✅ 進化版

```
這是今天產品團隊會議的隨手筆記（我打字很快所以很亂）。
請幫我整理成以下格式：

1. **決議事項** — 清楚的、可執行的結論
   （誰決定了什麼，有沒有提到截止日期）
2. **待辦任務** — 用表格呈現，欄位：
   任務 | 負責人 | 截止日 | 優先級
3. **未決問題** — 討論過但還沒結論的東西
   （這些需要後續跟進）
4. **重點討論摘要** — 給沒參加會議的人看的簡要摘要

如果筆記裡有看不懂的地方，標記 [不確定] 讓我知道要去確認。

以下是筆記：
---
討論 Q3 路線圖，Jen 想優先做 mobile app 的 redesign，
Mike 反對說應該先修 onboarding flow。
數據顯示 step 3 有 40% 的 drop-off。
最後同意這個 sprint 先做 onboarding 的 spike，
Sarah 負責帶隊。另外需要再招 2 個工程師，
但預算還沒過——Alex 週五前跟 finance 確認。
redesign 上線日還沒定，大概八月。
對了上週的 API 問題修好了，Tom 昨天 deploy 了⋯⋯
```

**結果**：結構漂亮的會議紀錄，讓你看起來是全場最有條理的人。[不確定] 的標記真的超實用——Claude 會抓到你自己漏掉的東西。

**可以偷的模式**：詳細定義*輸出結構*。Claude 很擅長把混亂的輸入整理成乾淨的輸出——但前提是你要告訴它*你要什麼結構*。

## 場景 5：九九乘法練習器

### ❌ 菜鳥版

```
做一個九九乘法的東西。
```

**結果**：一堆靜態的乘法題目印在螢幕上。「3 x 4 = ?」就寫在那裡。沒有互動。你的小孩 12 秒內就無聊到去滑 YouTube 了。

### ✅ 進化版

```
請用 Artifacts 做一個互動式九九乘法練習器，
給我 8 歲的女兒用。

功能要求：
- 隨機出乘法題（數字 1-12）
- 她打完答案後按「確認」
- 答對了：顯示有趣的動畫（碎紙片或星星）
  然後說些鼓勵的話（要輪流換不同的：
  「你超厲害！」「數學天才！」「帥呆了！」等等）
- 答錯了：溫柔地顯示正確答案，說
  「差一點點！再試一題！」（絕對不要顯示「錯！」
  ——我們要建立的是信心，不是恐懼）
- 計分器：在上方顯示「7 題對了 5 題」
- 難度選擇器：簡單（1-5）、中等（1-9）、困難（1-12）
- 設計：色彩豐富、活潑，大按鈕（她用 iPad 操作）
- 包含「重新開始」按鈕

整體的感覺應該是「鼓勵你的數學家教」而不是「嚇死人的考試」。
```

**結果**：一個你女兒真的會喜歡的互動式數學遊戲。鼓勵的話、難度選擇器、還有「絕對不說錯」的指示，讓它*感覺*像一個產品——因為它就是。你剛剛做了一個。

**可以偷的模式**：思考*使用者的體驗和情緒*。Claude 可以根據「氛圍」來設計，不只是根據規格。「鼓勵的數學家教，不是嚇死人的考試」比 50 行的功能清單告訴 Claude 更多。

## 五個改造背後的共通模式

注意這五個進化版有什麼共同點：

| 元素 | 它的作用 |
|------|---------|
| **具體細節** | 名字、日期、數字——不是模糊的占位符 |
| **對象意識** | 誰會看到這個？他們在乎什麼？ |
| **輸出格式** | 表格、條列、段落——定義好形狀 |
| **語氣/氛圍** | 要什麼*感覺*？不只是要什麼*內容*？ |
| **反向限制** | 什麼*不要*做？（不要用新細明體。不要說「錯！」） |
| **情境脈絡** | 業務背景、人際關係、底層目標 |

你不需要每次都全部包含。但用得越多，Claude 的第一版就越接近你腦中的畫面。

---

*以上的進化版 prompt 告訴了 Claude 我們**想要什麼**。但如果能教 Claude 我們**怎麼想的**呢？這就是範例的威力。下一節：「用給它看的」比「用說的」強一百倍。*
