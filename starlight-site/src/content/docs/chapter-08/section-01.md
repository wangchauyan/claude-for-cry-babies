## Ch1 的你 vs Ch8 的你

來，我們玩一個遊戲。下面這張表格對比了「第 1 章的你」和「第 8 章的你」。請誠實面對自己變了多少：

| 情境 | Ch1 的你 | Ch8 的你 |
|------|---------|---------|
| **有人給你看一段程式碼** | 「不。不不不。讓我回去用 Excel。」 | 「嗯，這應該是 HTML。第 42 行好像有問題，我可以修。」 |
| **你有一個工具的點子** | 「要是我會寫程式就好了⋯⋯」 | 「讓我花 20 分鐘用 Claude 做一個出來。」 |
| **收到一份亂七八糟的 Excel** | 花三小時手動整理格式 | 上傳給 Claude，要求分析，五分鐘搞定 |
| **AI 給的結果不對** | 「AI 果然不行。我就說吧。」 | 「讓我重新描述需求，多給一些上下文。」 |
| **有人問你會什麼** | 「我不太懂技術⋯⋯」 | 「我會用 AI 做工具。要看看嗎？」 |
| **你遇到一個 Error** | 恐慌。關掉分頁。假裝什麼都沒發生。 | 「這只是 Claude 在問我要更多資訊。讓我 debug 一下。」 |
| **你需要寫週報** | 打開 Word。盯著空白頁面。小聲哭泣。 | 打開你自己做的週報產生器。 |
| **有人說「MVP」** | 「最有價值球員？」 | 「我這個週末就能做一個出來。」 |
| **你在工作中看到重複性任務** | 「事情就是這樣啊。」 | 「這可以自動化。讓我試試看。」 |

## 這不只是技能的差異

再看一次那張表格。左邊那欄不是因為「缺少技能」。而是一種**心態**：「這不是我能做的事。我不是那種人。這件事需要找別人來做。」

右邊那欄也不是因為「擁有技能」。而是另一種心態：「我可以搞定這個。讓我試試看。我有工具可以幫忙。」

這本書真正的蛻變，不是你學會了寫 Prompt 或做 Artifacts。而是你從：

**「誰可以幫我？」** --> **「我可以怎麼解決？」**

這不是工具的切換。這是**身份認同的轉變**。而身份認同的轉變，才是真正能持續的改變。

### 以前的思維
> 「這個問題需要工程師來解決。」
> 「我又不會寫程式，能怎麼辦？」
> 「技術的事我不懂，交給專業的人。」

### 現在的思維
> 「這個問題我可以先用 Claude 做一個原型看看。」
> 「不會寫程式沒關係，我會描述需求。」
> 「讓我先驗證這個想法可不可行，再決定要不要找工程師。」

這種從「被動等待」到「主動創造」的心態位移，就是這本書送你的真正禮物。

## 你不知道自己學會的技能

當你以為自己只是在學「怎麼用 Claude」的時候，你其實已經在打造一套更廣泛的能力：

| 技能 | 你怎麼練出來的 | 還能用在哪裡 |
|------|-------------|------------|
| **清晰溝通** | 寫出能得到好結果的 Prompt | Email、簡報、對團隊下指令 |
| **系統性思考** | 把問題拆解成步驟給 Claude | 專案規劃、流程改善 |
| **迭代心態** | 透過多個版本改進 Artifacts | 任何創作或專業工作 |
| **除錯思維** | 診斷為什麼 Claude 的產出不對 | 幾乎所有領域的問題解決 |
| **產品思維** | 以使用者需求為中心做 MVP | 職涯發展、Side Project、創業 |
| **技術素養** | 在概念層面理解 HTML、資料格式、API | 跟工程團隊溝通、評估技術方案 |
| **行動偏好** | 動手做出東西而不是只停在企劃階段 | 所有事情。真的，所有事情。 |

你不只是「一個會用 AI 的人」。你是一個**用建造者思維來思考的人**。這件事大得多。

## 關於冒牌者症候群

差不多在這個時候，你腦中可能會冒出一個聲音：「但我不是*真正的*工程師啊。我只是在用 AI 幫我做事而已。」

讓我直接回應這件事：**那又怎樣？**

一個「真正的」攝影師用 Photoshop。一個「真正的」建築師用 CAD 軟體。一個「真正的」作家用拼字檢查、文法工具和研究資料庫。沒有人會因為他們使用了讓自己更有效率的工具，就質疑他們的專業正當性。

你正在使用這個十年最強大的工具來解決真實的問題、打造真實的東西。工具不會貶低你的工作。你的判斷力、你識別問題的能力、你描述需求的能力、你反覆迭代改進的能力 —— 這些全都是**你的**。

你不是一個用真工具的假建造者。你是一個用聰明工具的**真建造者**。
