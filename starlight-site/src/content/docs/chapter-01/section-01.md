## 一個真實的場景

你在公司當 PM，老闆突然說：「我們需要一個簡單的內部工具來追蹤每週進度。」

你心想，這聽起來很合理。然後你打開 Google，搜尋「如何做一個追蹤工具」，跳出來的第一個結果要你安裝 Node.js。

你點進去，看到一個黑色的視窗叫你輸入指令。你照做了：

```
$ npm install -g create-react-app

npm ERR! code EACCES
npm ERR! syscall access
npm ERR! path /usr/local/lib/node_modules
```

然後它噴出 200 行紅色的錯誤訊息。

你關掉視窗，打開外送 App，點了一杯珍奶安慰自己。

**這不是你的錯。** 這是工具的門檻太高了。但從今天開始，這個場景不會再發生。

## 時代變了：說話就是寫程式

在過去幾年裡，「有想法」和「做出東西」之間的牆被炸了。不是降低了，不是變薄了，是直接**炸碎了**。

新的程式語言？**就是你平常說的話。**

| 舊世界 | 新世界 |
|---|---|
| 學 Python 學六個月 | 用一句話描述你要什麼 |
| 在 Stack Overflow 爬文到凌晨兩點 | 凌晨兩點問 Claude（它不會批判你） |
| 看到報錯訊息想摔電腦 | 跟 Claude 說「這壞了，幫我修」 |
| 花五萬請工程師做一個小工具 | 花五分鐘對話就搞定 |

這不是誇大。這是現在正在發生的事。零程式經驗的人正在用 AI 做出工具、網站、資料分析、自動化流程 — 就靠清楚地說話。

關鍵字是**清楚地**。我們會在第 2 章花整章來教這件事。

## 但先別太嗨

**AI 不是魔法棒。** 它更像是一個**超強的實習生。**

想像你遇過最厲害的實習生：聰明、快速、熱心、知識量驚人。但如果你跟這個實習生說「幫我做個東西」：

- 他**會**做出一個東西
- 但可能不是你要的那個東西
- 而且他會非常有自信地做錯
- 成品會很......有創意

好結果和「這是什麼鬼」之間的差別，不在 AI 的智商。**在你的指令品質。**

**爛指令：**「幫我寫個報告。」
*結果：一份關於鯨魚生態的讀書報告。技術上來說，是報告沒錯！*

**好指令：**「幫我寫一份 500 字的專案進度報告給我的主管。專案目前延遲三週，原因是廠商交期延誤。語氣要專業但不要太緊張。附上修改後的時程表，以及我們需要主管支援的部分。」
*結果：一份你直接貼上 Email 就能寄出的報告，可能比你自己寫的還好。*

同一個 AI，同一顆腦袋，天差地別的結果。差異在哪？**在你。**

## 你真正在學的技能

所以這本書的真正賣點，不包裝：

你不是在學寫程式。你不是在學「AI」。你是在學**怎麼想清楚你要什麼，然後有效地溝通出來**。

這個技能會幫你：
- 更好地使用 AI 工具（當然）
- 寫出更好的 Email（真的）
- 對同事和團隊下更清楚的指令（他們會感謝你）
- 更系統化地思考問題

換句話說：就算明天 AI 消失了，這些技能依然讓你在職場上更強。但 AI 不會消失，它每個月都在變更厲害。而現在就學會跟它合作的人，正在累積一個隨時間複利成長的職業超能力。

## 為什麼叫「Cry Baby」？

為什麼叫哭包？因為我們都曾經在那裡。我們都曾經盯著螢幕覺得自己是白痴。我們都曾經想哭，因為東西壞了而我們完全不知道為什麼。

這本書驕傲地戴著這個標籤。**覺得迷茫，是每段學習旅程的起點。**「哭包」和「專家」的唯一差別是：專家先哭了一場，然後繼續往前走。

那我們就繼續走吧。
