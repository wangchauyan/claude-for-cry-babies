## 關於點子的殘酷真相

你有很多點子。可能還是很棒的點子。問題不在你的想像力 -- 而在於分辨哪些點子**能用 Claude + Artifacts 在一個週末做出來**，哪些會把你拖進三個月的挫折深淵。

這一節是來救你脫離你自己的。

---

## 適合的：放膽去做

以下這些類型的專案，非常適合不會寫程式的人用 Claude Artifacts 來做：

| 類型 | 範例 | 為什麼適合 |
|------|------|-----------|
| **計算器與轉換器** | 小費計算機、單位換算、房貸估算器 | 簡單的輸入-輸出邏輯，不需要後端 |
| **內容產生器** | 週報產生器、社群貼文撰寫器、Email 草稿工具 | 文字進去、格式化文字出來 -- Claude 的拿手好戲 |
| **儀表板與追蹤器** | 習慣追蹤器、支出總覽、專案進度看板 | 視覺化呈現資料，Artifacts 最適合 |
| **教學互動工具** | 單字卡、Quiz 測驗產生器、九九乘法練習 | 互動式學習完美契合單頁應用 |
| **小遊戲與趣味工具** | 猜數字、記憶翻牌、心理測驗、抽獎轉盤 | 獨立運作、不需伺服器、即時滿足感 |
| **表單與問卷** | 活動報名表、意見回饋收集器、客戶需求表 | 輸入欄位 + 顯示結果 = Artifacts 甜蜜點 |
| **參考工具** | 速查表、比較表格、快速查詢指南 | 把資訊整理得漂漂亮亮 |

共同特點？**所有事情都發生在一個頁面裡。** 不需要登入。不需要資料庫。不需要伺服器。就是一個獨立的工具，把一件事做好。

---

## 不適合的：別碰（至少現在別碰）

這些點子很有誘惑力，但會讓你哭 -- 而且不是那種驕傲的哭：

| 類型 | 為什麼會出事 | 你其實需要的是 |
|------|-------------|---------------|
| **需要登入系統** | 認證需要伺服器、資料庫、安全機制 | 後端基礎設施、密碼加密、Session 管理 |
| **需要資料庫** | 關掉分頁，資料就不見了 | 真正的資料庫（PostgreSQL、Firebase 等） |
| **需要即時通訊** | 需要 WebSocket、伺服器、多人連線 | 有即時通訊能力的後端伺服器 |
| **需要付款功能** | Stripe、安全合規、金錢處理 | PCI 合規、金流 API、可能還需要律師 |
| **需要操作手機硬體** | 網頁沒辦法控制手機的相機或藍牙 | 原生 App 開發（Swift、Kotlin） |
| **多人即時協作** | 即時同步很難做 | 後端、WebSocket、衝突解決邏輯 |
| **內建 AI 功能** | 你沒辦法在 Artifact 裡面跑 AI 模型 | API 金鑰、伺服器、AI 服務串接 |

**懶人判斷法**：如果你的點子需要*在不同次使用之間記住東西*或*跟其他服務溝通*，那它就不是 Artifacts MVP。它可能是個好點子，但需要不同的工具（第 8 章會提到）。

## 三個問題選題法

在你決定做什麼之前，先把你的點子丟進這三個問題裡：

### 問題 1：「這個問題夠痛嗎？」

| 你的答案 | 判定 |
|---------|------|
| 「有的話不錯啦」 | 大概不值得做 -- 你會半途失去動力 |
| 「我每週都在處理這個煩人的事」 | 現在開始有意思了 |
| 「我昨天才在抱怨這件事」 | 快去做。現在就做。 |

最好的 MVP 解決的是你自己親身感受到的痛點。如果你不在乎這個問題，你也不會在乎解決方案。

### 問題 2：「一句話能說清楚它做什麼嗎？」

| 描述 | 判定 |
|------|------|
| 「它就像 Notion 加 Slack 加 Trello 但有 AI 而且還能追蹤心情然後...」 | 太多了。多到不行。砍。 |
| 「你輸入職稱，它幫你產生面試練習題」 | 完美。清楚、簡單、做得出來。 |
| 「幫團隊決定中午吃什麼」 | 很好。具體的問題，明確的解法。 |

如果你沒辦法用一句話說完，你的範圍太大了。砍功能，直到塞得進一句話。然後再砍一個。

### 問題 3：「它能是一個單頁 Artifact 嗎？」

| 你的答案 | 判定 |
|---------|------|
| 「需要多頁面加導航」 | 先簡化成一個頁面吧 |
| 「需要永久儲存資料」 | 不是 Artifacts MVP -- 考慮其他方案 |
| 「所有事情都在一個畫面上完成」 | 完美契合 Artifacts |

## 好點子 vs. 壞點子的評分矩陣

如果你有好幾個點子在腦子裡打架，用這個簡單的評分表來決定：

| 評分項目 | 1 分（差） | 3 分（普通） | 5 分（好） |
|---------|-----------|-------------|-----------|
| **痛感** | 「有也好沒有也好」 | 「偶爾會遇到」 | 「每週都在痛」 |
| **簡單度** | 需要多頁面 + 資料庫 | 需要一些複雜邏輯 | 一頁搞定 |
| **可展示性** | 很難跟別人解釋 | 需要 demo 才懂 | 截圖就能說明 |
| **你的熱情** | 「好像應該做」 | 「做做看吧」 | 「我超想用這個！」 |

**15 分以上**：立刻動手！
**10-14 分**：可以做，但考慮簡化範圍。
**10 分以下**：換一個點子吧，這個會讓你半途而廢。

## 問題-解決方案適配度測試

最後一個檢測：你的點子有沒有「問題-解決方案適配」（Problem-Solution Fit）。

這個概念很簡單：**你的解決方案真的能解決那個問題嗎？**

聽起來像廢話，但你會驚訝有多少人做了一個工具，結果它解決的不是使用者真正的痛點。

試試這個填空練習：

```
我注意到 [某類人] 每次遇到 [某個問題] 的時候，
都會 [他們目前的笨方法]。

我的工具可以讓他們 [更好的做法]，
只需要 [簡單的步驟]。
```

如果你能流暢地填完這四格，你的問題-解決方案適配度很高。如果你卡在某一格... 也許你需要重新想想你到底在解決什麼問題。
