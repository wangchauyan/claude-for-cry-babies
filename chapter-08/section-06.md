# 8.6 進階之路：當你開始用 Claude Code

> *這一節是給準備再跨一步的讀者。如果你現在已經覺得「網頁版 Claude 夠我用了」，可以先跳過。但如果有一天你想從「做小工具」進化到「做完整的軟體專案」——回來看這節，它會是你的指南針。*

---

## 從 Claude.ai 到 Claude Code

前面七章，我們都在 Claude.ai 的網頁介面上工作。這很好——對大部分場景已經足夠。

但當你的專案變大——不再是一個 Artifacts 能塞下的單檔案，而是有十幾個檔案、需要安裝套件、需要跑起來的「真正的程式」——你會需要一個更強的工具：**Claude Code**。

Claude Code 是 Claude 的命令列版本。它可以：
- 直接讀取和修改你電腦上的檔案
- 執行指令（安裝套件、跑測試、啟動伺服器）
- 幫你建立完整的軟體專案

> 把 Claude.ai 想成「你在白板上跟 AI 討論」，Claude Code 就是「你讓 AI 坐在你旁邊，直接操作你的電腦幫你做事」。

聽起來很嚇人？其實操作方式跟你在 Claude.ai 打字完全一樣——只是它的「手」可以碰到你的檔案了。

---

## Git：不只是工程師的工具

當你開始用 Claude Code（或 Cursor、Replit 這類工具），有一個東西會變得極其重要：**Git**。

你可能聽過 Git 是「版本控制工具」，覺得「那是工程師的事」。但它的本質非常白話：

> **Git 就是一台時光機 + 一本自動日記。**

每次你（或 AI）修改了檔案並「存檔」（在 Git 的世界叫 commit），它會：
1. 記錄你改了什麼
2. 記錄你為什麼改（commit message）
3. 記錄什麼時間改的
4. 保留修改前的完整快照

改壞了？一個指令就能回到五分鐘前、一小時前、甚至一個月前的狀態。

---

## 為什麼 AI 比人類更需要 Git？

還記得第六章我們討論的「Claude 每次對話都像失憶」嗎？

Claude Code 也有同樣的問題。它的記憶（Context Window）就像你大腦的工作記憶——能同時記住的東西有上限。當你的專案有幾十個檔案、開發了好幾週，它不可能把所有歷史都記在腦子裡。

**這時候 Git 就是 AI 的外接記憶體。**

想像一個情境：你昨天跟 Claude Code 一起改了十個檔案，今天開了新的對話繼續。新的 Claude 什麼都不記得。但如果你有 Git，它可以：

```
git log --oneline -10
```

一秒看到：
```
abc1234 加上深色模式切換功能
def5678 修正手機版的排版問題
ghi9012 建立使用者登入頁面
...
```

不用你花十分鐘重新解釋「我們昨天做了什麼」。**Git log 就是前情提要。**

---

## 記憶其實不只兩層

你可能以為 AI 的記憶就兩種：正在用的短期記憶，和一張手寫的便利貼。

實際上 Claude Code 有好幾層記憶，各有各的分工：

| 記憶方式 | 白話翻譯 | 怎麼運作 | 適合存什麼 |
|----------|---------|----------|-----------|
| **CLAUDE.md** | 專案規則卡 | 每次開工自動全部載入 | 穩定的規則、慣例、build 指令 |
| **Auto Memory** | AI 自己的筆記本 | Claude 自動記錄、自動回顧 | 踩過的坑、學到的教訓 |
| **Session Memory** | 上次的摘要 | 自動產生、自動帶入，你不用管 | 上一次對話做了什麼 |
| **Git History** | 完整的日記 | 需要時主動翻閱 | 做過什麼、為什麼、什麼時候 |

判斷該放哪一層，看的不是資訊的種類，而是**你多常需要它**：

- 每次都要看 → CLAUDE.md
- 每次自動帶入（你不用管） → Session Memory / Auto Memory
- 偶爾需要查 → Git

一個常見的錯誤是把所有歷史都塞進 CLAUDE.md ——就像把日記本的每一頁都貼在便利貼上。便利貼要保持簡潔，日記自然會累積。

---

## Git 幫 AI 做的四件事

### 1. 重建脈絡：「前情提要」

新的 AI session 啟動時，看一下最近的 commit 紀錄就能快速進入狀況。

就像你接手一個同事的專案時，看他的工作日誌比聽他口頭講一小時更快更準。

### 2. 精準回溯：「當初為什麼這樣寫？」

每一行程式碼都帶著歷史——誰寫的、什麼時候寫的、搭配什麼說明。

當 AI 遇到一段看不懂的程式碼，它可以查到「三個月前的自己」留下的註解：「這裡要這樣寫是因為 XX 的限制。」

### 3. 安全探索：「搞砸了也不怕」

這是最重要的。有了 Git，你可以放心讓 AI 去大膽嘗試：
- 想重構整個頁面？先 commit 目前的版本，然後放手去改
- 改壞了？一個指令回到安全點
- 想同時嘗試兩種做法？開兩個分支（branch），各試各的

沒有 Git 的時候，AI 搞壞一個檔案就得手動復原。有了 Git，就算 AI 把整個資料夾刪了，也能一鍵復活。

### 4. 交接傳承：「下一個人接手」

不管是下一個 AI session、另一個 AI 工具、還是一個真正的人類工程師——Git 紀錄讓任何人都能快速理解這個專案的來龍去脈。

## 一個簡單的心智模型

```
CLAUDE.md      = 地圖（我在哪、要去哪、有什麼規則）
Auto Memory    = AI 自己的便利貼（踩過的坑、學到的教訓）
Session Memory = 昨天的摘要（自動產生，不用你管）
Git            = 足跡（我走過哪些路、為什麼在這個路口轉彎）
```

地圖要保持簡潔——塞太多資訊反而找不到重點。
足跡自然累積——每次前進就留一個標記，需要回頭時再查。
中間兩層 Claude 自己會管，你不用操心。

---

## 你現在不需要學 Git，但請記住它

如果你是本書的主力讀者（PM、行銷、設計師），你**現在**不需要去學 Git。

但請把以下三句話存在腦裡：

1. **Git 是時光機** — 任何修改都能還原
2. **Git 是 AI 的日記本** — 讓失憶的 AI 能快速回憶
3. **Git 是最好的安全網** — 比「記得按 Ctrl+Z」可靠一萬倍

當有一天你發現自己：
- 開始用 Cursor 做更複雜的專案
- 開始用 Claude Code 直接操作檔案
- 專案大到「改壞了不知道怎麼救」

那時候回來看這一節，然後去學 Git。學習曲線大概兩個下午，而投資報酬率會讓你覺得相見恨晚。

---

> *「工具的力量不在於它有多複雜，而在於你知道它存在，並且知道什麼時候該拿起它。今天你知道了 Git 這台時光機的存在——哪天需要它的時候，你不會手足無措。」*
